# cinema-backend

Go backend for fazon.nexus/cinema: scrapes UK cinema showtimes (port of
`cinema-listings/cinemas.py`) and serves `listings.json` at `https://cinema-api.fazon.nexus`.

Coverage: every UK cinema of the big chains (Odeon, Cineworld, Vue, Everyman, Showcase,
Picturehouse, Curzon, The Light, Reel), listed in `internal/registry/chains.json` (generated by
`cinema discover` from the chains' own sites), plus hand-written independents around Greater
Manchester and Yorkshire, and the small chains Arc and Parkway (`internal/registry/registry.go`, `places.go`). Each cinema has a region
(`internal/region`: England's nine regions, Scotland, Wales, Northern Ireland) and the API serves
one selection of regions at a time.

Odeon, Cineworld, Vue, Curzon and the taposapp independents (Plaza Cinema Skipton, Picture House Keighley, Rex Cinema Elland) return 403 to the Hetzner IP, so they are
flagged `Relay` and scraped by `cinema-relay` on a residential connection, which uploads raw
results to the server. The server scrapes the rest itself.

Scraping is tiered so nationwide coverage doesn't multiply the traffic: cinemas in a **hot** region
(the default regions, or one somebody requested in the last 48 h) refresh every 2 h (server) / 3 h
(relay); the rest of the country refreshes daily, at most 40 cold cinemas per round. The first
request for a cold region wakes the server's scraper at once, and the relay picks it up on its
next 30-minute run, so those cinemas show "last updated N hours ago" until then.

```
cmd/cinemad        server: scrape loop + HTTP API
cmd/cinema-relay   home PC: scrape relay cinemas, upload
cmd/cinema         local CLI for testing / parity
internal/scrape    impersonating HTTP client (tls-client, Chrome 146), Show model, tag normalisation, runner
  chains/          Vista (Odeon, Curzon), Webedia (Cineworld, Everyman, Showcase), Vue, Picturehouse, The Light, Reel
  ticketing/       Indy GraphQL, TicketSource, Spektrix (+ their venues)
  venues/          Savoy CCM, taposapp (Skipton, Keighley, Elland), Admit One (Arc, Parkway Barnsley, Lockworks), Glitterfish (Parkway), Jacro (Prince Charles, Cottage Road, Cinemac), Penistone, Pictureville, Stockport Plaza, Tideswell
internal/registry  every cinema (name, chain, URL, Relay flag, fetcher, location, region); chains.json embedded
internal/chainfile chains.json format
internal/discover  `cinema discover`: each chain's cinema list + locations (postcodes.io for regions)
internal/region    the 12 regions and the default selection
internal/listings  build(): window, dedupe, Classic rule, runtime medians, end estimates, travel matrix; places
internal/store     per-cinema last-good results on disk
deploy/            systemd units, env example, Caddy snippet
```

## Build

```sh
go test ./... && go vet ./...
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o bin/cinemad ./cmd/cinemad
go build -trimpath -o bin/cinema-relay ./cmd/cinema-relay
go build -o bin/cinema ./cmd/cinema
```

Local scrape (same output as `python3 cinemas.py`):

```sh
bin/cinema scrape [--only odeon,vue] [--days 16] [--out listings.json] [--raw-out raw.json] [--relay|--server]
bin/cinema build --raw raw.json --out listings.json   # rebuild from a raw dump, no network
```

Refresh the chain list (run from a residential IP: Odeon/Cineworld/Vue block datacentres), review
the diff, then rebuild and deploy both binaries:

```sh
bin/cinema discover [--only odeon,vue]                 # rewrites internal/registry/chains.json
git diff --stat internal/registry/chains.json
```

Discovery keeps a cinema's published name (matched by chain + id), and keeps a chain's previous
entries when that chain fails or suddenly returns under half as many cinemas.

## API

- `GET /v1/listings.json?regions=north-west,yorkshire` — the cinemas of those regions (comma-separated
  `internal/region` keys; none = `CINEMAD_REGIONS`, default north-west, yorkshire, east-midlands; an
  unknown key is a 400). Adds `regions` (every region with its cinema count), `region` (the keys
  served) and a `region` per cinema. Requesting a region makes it hot for 48 h.
  Window today..today+15 (Europe/London), the frontend's schema plus per-cinema
  `updated` (last successful scrape, RFC 3339) and `stale` (no success in 12 h); `generated` is RFC 3339.
  For privacy there is no `home` and no Home row in `travel` (the page adds home legs itself from
  `travel.estimate` and the visitor's postcode). gzip, ETag/304,
  `Cache-Control: public, max-age=300`, CORS for `CINEMAD_ORIGINS` (default fazon.nexus, localhost:1313, 127.0.0.1:any).
- `POST /v1/ingest` — `Authorization: Bearer <token>`, body (optionally gzip)
  `{"results":[{"name","shows":[{film,start,screen,formats,url,end,duration}],"error","fetched"}]}`.
  Only relay cinemas unless `?any=1`. A result with an error keeps the cinema's previous shows.
- `GET /v1/relay/due[?limit=N]` — `Authorization: Bearer <token>`: the relay cinemas to scrape now
  (`{"cinemas":[…],"hot":n,"cold":n}`): every due hot-region one plus up to N (default 40) cold ones.
- `GET /v1/feedback` — the planner's public feedback: `{items:[{id,name,text,created,replies?:[{id,name,text,created}]}] (newest first), limit, used,
  remaining, max_chars, max_name, resets_at, now}`; `no-store`.
- `POST /v1/feedback` — no login; JSON `{"name","text"}` (name optional, ≤40 chars; text ≤1000 chars). Quota:
  5 posts per UTC day **across everyone** (429 when used up); deleting a post doesn't free its slot.
  Stored in `<data>/feedback/feedback.json`.
- `DELETE /v1/feedback/{id}` — moderation, `Authorization: Bearer <token>` (same token as ingest), e.g.
  `ssh root@89.167.79.200 'source /etc/cinemad/env; curl -X DELETE -H "Authorization: Bearer $CINEMAD_INGEST_TOKEN" http://127.0.0.1:8090/v1/feedback/<id>'`.
- `POST /v1/feedback/{id}/replies` — owner reply, same token; JSON `{"text"}` (≤2000 chars; `name` optional, default
  "Faizan"). Doesn't use the daily quota. `DELETE /v1/feedback/{id}/replies/{rid}` removes one.
  `GET /v1/feedback/owner` answers 204 for a good token. The page's owner mode (`/cinema/?owner`, token kept in
  localStorage) uses these to reply and delete from the browser.
- `GET /healthz`

## Deploy (Hetzner)

```sh
# DNS: A record cinema-api.fazon.nexus -> the server's IP
openssl rand -hex 32                              # ingest token
scp bin/cinemad deploy/cinemad.service deploy/env.example root@SERVER:/tmp/
ssh root@SERVER '
  useradd --system --no-create-home --shell /usr/sbin/nologin cinemad
  install -m 0755 /tmp/cinemad /usr/local/bin/cinemad
  install -d -m 0750 -o root -g cinemad /etc/cinemad
  install -m 0640 -o root -g cinemad /tmp/env.example /etc/cinemad/env   # then edit: set CINEMAD_INGEST_TOKEN
  install -m 0644 /tmp/cinemad.service /etc/systemd/system/cinemad.service
  systemctl daemon-reload && systemctl enable --now cinemad
  journalctl -u cinemad -n 50 --no-pager
  curl -s localhost:8090/healthz'
```

Add `deploy/Caddyfile.snippet` to `/etc/caddy/Caddyfile`, then `systemctl reload caddy`.
Upgrade: copy the new binary to `/usr/local/bin/cinemad`, `systemctl restart cinemad` (data in
`/var/lib/cinemad` survives).

## Relay (home PC)

```sh
install -Dm0755 bin/cinema-relay ~/.local/bin/cinema-relay
install -Dm0600 /dev/stdin ~/.config/cinema-relay/token <<< 'THE-TOKEN'
cinema-relay --dry-run                            # scrape only, print a summary
cinema-relay                                      # scrape + upload; exits 1 if the upload fails
cp deploy/cinema-relay.{service,timer} ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now cinema-relay.timer
loginctl enable-linger "$USER"                    # optional: run while logged out
journalctl --user -u cinema-relay -n 30
```

With no flags it scrapes what `GET /v1/relay/due` lists (the timer runs it every 30 min; most runs
are short). `--every-relay` scrapes every relay cinema, `--all` every cinema, `--only x,y` a subset
(non-relay cinemas are sent with `?any=1`); `--limit N` caps this run's cold-region cinemas.

## Adding a cinema

Big-chain cinemas come from `cinema discover` (above). A new chain needs a fetcher, a discovery
function in `internal/discover` and a case in `registry.chainFetcher`. An independent:

1. Write or reuse a fetcher (`scrape.Fetcher`: `func(*scrape.Session, from, to time.Time) ([]scrape.Show, error)`)
   in the package for its platform. Use `s.GetOK`/`GetJSON`/`PostJSON` (Chrome-impersonating, one
   cookie jar per cinema run); start/end are naive UK wall-clock `2006-01-02T15:04`.
2. Add it to `internal/registry/registry.go` (set `Relay: true` if it 403s from the server:
   `curl -sI <url>` on the box).
3. Add its coordinates and region to `registry.Places` (the registry test fails otherwise).
4. `go test ./... && bin/cinema scrape --only <name>`, then deploy the server (and the relay if it's a relay cinema).

## Notes

- Expected values in the unit tests (`tags_cases_test.go`, `title_cases_test.go`,
  `listings/testdata/rules_*.json`, the ticketing/venues tables) were generated from the Python
